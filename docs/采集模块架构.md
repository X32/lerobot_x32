# 采集模块架构（Data Collection）

> 本文整理自 v0.7.1 源码分析（2026-11），是 [`ARCHITECTURE.md`](../ARCHITECTURE.md) 中"采集"环节的展开。
> 对应上游源码自带的注释图：`src/lerobot/scripts/lerobot_record.py` 的 `record_loop()` docstring。

## 采集模块在哪

| 层 | 位置 | 职责 |
|---|---|---|
| 入口脚本 | `src/lerobot/scripts/lerobot_teleoperate.py` / `lerobot_record.py` | 前者纯遥操作不存数据，后者遥操作+录制 |
| 主臂 | `src/lerobot/teleoperators/`（so101_leader 等） | 读人手动作 |
| 从臂 | `src/lerobot/robots/so_follower/` | 读状态、执行动作（SO-100/SO-101 共用此目录） |
| 相机 | `src/lerobot/cameras/`（opencv/intelrealsense 等） | 读图像帧 |
| 电机总线 | `src/lerobot/motors/`（feetech/dynamixel…） | sync_read/sync_write |
| 落盘 | `src/lerobot/datasets/`（`dataset_writer.py`、`image_writer.py`、`video_utils.py`） | 组装 episode、异步写 parquet/mp4 |

## 采集主循环架构

```
   teleoperator(主臂)                     robot(从臂+相机)
        │ get_action()                        │ get_observation()
        ▼                                     ▼
 teleop_action_processor            robot_observation_processor
   (动作处理链，如重定向/对齐)              (观测处理链)
        │                                     │
        └──────────► robot_action_processor ◄─┘
                          │  (合成要发给从臂的目标动作)
                          ▼
                 robot.send_action()  ← send 前有 ensure_safe_goal_position 限幅保护
                          │
        ═══ 每帧循环 @ fps(默认30)，固定节拍 ═══
                          │
            该帧的 (processed_obs, processed_teleop_action)
                          ▼
              LeRobotDataset.add_frame() 写入
              ├─ 图像 → 异步队列 ─► worker 线程池 (image_writer.py:172) ─► 缓存帧 ─► ffmpeg 编码 mp4
              └─ 数值+时间戳 ─► parquet
                          ▼
              一条 episode 结束：视频编码收尾、meta(帧数/时长/任务)更新
       并行支线：display_data → rerun/foxglove 实时可视化；play_sounds 语音提示
```

关键工程设计：

- **固定频率节拍**：每个 tick 同时采主臂、从臂、相机，时间戳均匀——这是 BC 训练能对齐观测-动作的前提。
- **异步写盘**：图像走 queue + 线程池后台落盘/编码（`image_writer.py`），IO 永不阻塞主循环，采集不掉帧。
- **processor 链挂三个口**：观测、遥操动作、下发动作各挂一条 `ProcessorStep` 链，采集时就把数据规范成策略要的格式。
- **安全兜底**：动作限幅（`so_follower.py:208` `ensure_safe_goal_position`）+ `@safe_stop_image_writer`（出错时把缓冲帧安全落盘再退出，不丢数据）。

## 采集到的数据（SO-101 单臂为例）

每帧一条记录：

| 字段 | 内容 | 来源 |
|---|---|---|
| `observation.state` | 6 个关节当前位置：`shoulder_pan.pos`、`shoulder_lift.pos`、`elbow_flex.pos`、`wrist_flex.pos`、`wrist_roll.pos`、`gripper.pos`（float，校准后角度） | 从臂电机总线 `Present_Position` 同步读 |
| `observation.images.*` | 每个相机的 RGB 帧 (H,W,3)，可加 `_depth` 深度图 | `cameras/` |
| `action` | 6 个关节**目标**位置 = 主臂对应关节位置（经映射+限幅） | 主臂 |
| `timestamp` / `frame_index` / `episode_index` / `task_index` | 时间与 episode/任务元数据 | 循环生成 |

特征定义见 `so_follower.py:99-104`：`observation_features = 电机特征 + 相机特征`，`action_features = 电机特征`——**动作和状态共用同一个 6 维关节空间**，这是 SO-101 这类主从同构臂的特点（leader 的关节角直接当 follower 的目标）。

## 落盘后的数据集结构（v3 格式）

```
<username>/<dataset_name>/
├── meta/
│   ├── info.json          # fps、特征 schema、chunk 划分、视频路径模板
│   ├── episodes.parquet   # 每条 episode：帧数、时长、涉及任务
│   ├── tasks.parquet      # 任务自然语言描述（"Grab the cube"）
│   └── stats.*            # 各特征均值/方差（训练时归一化用）
├── data/chunk-000/file-000000.parquet          # 数值列：state、action、timestamp…
└── videos/chunk-000/<camera_key>/episode-000000.mp4  # 每相机一个视频文件
```

**为什么图像存 mp4、数值存 parquet**：30fps 的 640×480 图像存原始数组一天就是几十 GB，视频编码省几十倍空间，训练时按时间戳抽帧解码；而 state/action 这类要随机访问、要算统计量的小数据放 parquet。

该格式已是 Hugging Face Hub 上机器人数据集的事实标准：录制后可直接 `push_to_hub`，他人用 `LeRobotDataset("<user>/<dataset>")` 一行加载。
