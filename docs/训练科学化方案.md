## 2. 训练：按 epoch 缩放，不按固定步数

**v1 的问题**：三个 run 都跑 50k 步，但数据量差 4 倍 → s10 见 84 epoch、s41 只见到 20 epoch，"数据量曲线"里混进了算力变量。

**v2**：统一 **20 epoch**，步数按帧数缩放（batch 8，`steps ≈ 20 × frames / 8`）：

| run | 训练条数 | 帧数 | 步数（20 epoch） | 预估耗时 @3.4 step/s |
|---|---|---|---|---|
| s10 | 10 | 4 848 | **12 100** | ~1.0h |
| s25 | 25 | 12 265 | **30 700** | ~2.5h |
| s41 | 41 | 19 502 | **48 800** | ~4.0h |
| 合计 | — | — | ~91 600 | **~7.5h**（比 v1 的 12.6h 省 5h） |

> 帧数为实测；有效样本会略少于帧数（尾部窗口 padding），以日志首个 epoch 的实际步数为准。

### 2.1 命令模板

```bash
PYTHONPATH= nohup uv run --no-sync lerobot-train \
    --dataset.repo_id=zihao/so101_task1 \
    --dataset.root=/mnt/nvme_data/huggingface_cache/lerobot/zihao/so101_task1 \
    --dataset.episodes='[<训练集列表>, <验证集列表>]'   # ⚠️ 验证集 10 条必须在最后
    --dataset.eval_split=<见下表> \
    --policy.type=act --policy.push_to_hub=false \
    --output_dir=outputs/train/<run名> \
    --steps=<见上表> --batch_size=8 --save_freq=10000 --log_freq=200 \
    --eval_steps=5000 --max_eval_samples=0 \
    --num_workers=4 --seed=1000 \
    > outputs/<run名>.log 2>&1 &
```

`eval_split` 取值表（`ceil(N×frac)=10` 的解，N=训练+验证总条数）：

| run | 训练条数 | N | eval_split | episodes 列表 |
|-----|---------|---|-----------|---------------|
| s10 | 10 | 20 | **0.500** | 训练 `[1,6,11,16,21,26,31,36,41,46]` + 验证 |
| s25 | 25 | 35 | **0.285** | s10 的 10 条 + `[2,3,7,8,12,13,17,18,22,23,27,28,32,33,37]` + 验证 |
| s41 | 41 | 51 | **0.196** | 全部 41 条训练集 + 验证 |

验证集列表（三个 run 固定不变，放最后）：`[0,5,10,15,20,25,30,35,40,45]`

**机制说明**（源码核实）：`factory.py:253` 按 task 取"最后 `ceil(n×frac)` 条"，且 `resolve_episode_indices` 明确"input order is preserved"、`lerobot_dataset.py:293` 直接 `self.episodes = episodes` 不排序。**顺序即语义**，这是本方案成立的前提。

### 2.2 启动前置断言（v1 缺，必加）

`eval_split` 差 0.001 就会切出 9 或 11 条，而且**不会报错**。启动 30 秒后执行：

```bash
grep -m1 "Train/eval split" outputs/<run名>.log
# 必须看到 "... 10 eval"，且训练条数等于上表；不符立即 kill 重算
```

### 2.3 为什么 `--max_eval_samples=0`

`lerobot_train.py:499-506` 的抽样是 `frames = (task_arr == t).nonzero()[0][:per_task]`——**取每个 task 的前 N 帧**，不是均匀抽样。val 顺序是 `[0,5,10,15,…]`，`max_eval_samples=2048` 时只覆盖 ep0(753)+ep5(689)+ep10(538)+68 帧 ≈ **3.1 条**，且全落在 11-18 批次。用它选 checkpoint 等于用一个偏向旧批次的子集在选。

改全量：4 648 帧 ≈ 581 个 batch，单次评估约 60–90s，`eval_steps=5000` 时每 run 10 次 ≈ 12 分钟，可接受。

## 3. 基线：state-only BC + 持久性参照（✅ 已修正）

**v1 的致命错误**：`delta_timestamps` 单位是秒，脚本传的是帧号 `list(range(100))`，实测被解释成 `[0,30,60,…,2970]` 帧。数据集 episode 长 538–897 帧，于是每条样本只有前 ~20 个位置是真动作，其余全被钳到末帧——"基线"实际在学"预测 episode 末帧"，且**不会报错**。

**v2 已修三处**（`myscript/train_bc_state.py`）：

1. `action: [i / fps for i in range(chunk)]`，并断言 `reader.delta_indices["action"] == list(range(chunk))`；
2. 损失与评估都过 `masked_l1`，忽略 `action_is_pad`（与 ACT 主损失同口径；v1 未加 mask）；
3. 移除 video/image 特征：LeRobotDataset 默认解码所有视频，实测 **0.236 s/批 → 0.004 s/批**（×60）。

**新增持久性参照**（0 参数）：100 步全部预测当前关节状态。它给出"不学也能达到的 L1"，是判断模型是否真的学到东西的下界；写在 `metrics.json` 的 `val_persist_raw`。

```bash
PYTHONPATH= nohup uv run --no-sync python myscript/train_bc_state.py \
    --steps 20000 --batch-size 256 --seed 1000 \
    --output-dir outputs/train/bc_state_task1 \
    > outputs/train_bc_state.log 2>&1 &
```

产物：`best.pt`（按 val L1 最优）+ `metrics.json`（含持久性曲线）。MLP 6→512→512→600 = **0.57M** 参数（v1 写的 0.9M 有误）；移除视频解码后 20k 步 < 1h。

**预算口径**：基线跑 20k 步 ≈ 263 epoch，远多于 ACT 的 20 epoch——这是**对基线有利**的设置（给足它机会）。若基线仍显著落后于 ACT，结论只会更强。

**这个基线能回答什么**：不用视觉能否完成本任务。
**不能回答什么**：视觉值多少——架构、chunking、VAE 都与 ACT 不同。视觉是否被利用，用 §5.4 的推理期图像置零消融回答。

## 4. 离线验证评估（checkpoint 选型）

```bash
PYTHONPATH= uv run --no-sync python myscript/eval_val_l1.py \
    --ckpt outputs/train/act_task1_s41_seed1000/checkpoints/<step>/pretrained_model
```

- 指标 `action_l1` = **masked、归一化空间**的 L1；ACT 评估模式下 `eval_loss` 与之同值（无 KL 项）。
- 默认跑满全量 val（4 648 帧），不要用 `--max-batches` 截断做选型。
- 逐 ckpt 填表（**按验证 L1 选，不按训练 loss**）：

| run | 最优 step | val L1（归一化） | 持久性参照（raw） | 真机成功率 [Wilson 95% CI] |
|-----|-----------|-----------------|------------------|---------------------------|
| 持久性（0 参数） | — | — | 12.513 | — |
| bc_state 基线 | 1000 | —（raw 10.827） | 12.513 | |
| s41 | **20000** | **0.4274** | — | |
| s25 / s10 | 训练中 / 待跑 | | — | |
| 51 条无切分（污染参考） | 100000 | ⚠️ 偏乐观 | — | |

**s41 全 checkpoint 曲线**（2026-11-23 全量评估，最优 = `checkpoints/020000/pretrained_model`）：

| step | 10k | 20k | 30k | 40k | 50k |
|------|-----|-----|-----|-----|-----|
| val L1 | 0.4661 | **0.4274** | 0.4408 | 0.4495 | 0.4444 |

- 20k 后回升并平台化（0.44~0.45）：过拟合形状实锤，**后续 seed 跑 `--steps=30000` 即可**（20k 最优 + 余量），每跑省 2.5h；
- 训练中抽样 eval（2048 帧）与离线全量（4648 帧）最低点一致（均为 20k），口径交叉印证。

> 跨 run 的归一化 L1 只做粗对比（不同子集的归一化统计略有差异）；**数据量结论以真机成功率曲线为准**。

## 5. 真机 rollout 协议（v1 的 10 次单位置已废弃）

### 5.1 成功判定（写死）

积木完全落入盒内、夹爪松开并退出、全程无人工干预、60s 内完成。四条同时满足才算成功。

### 5.2 两个条件，每配置 20 次

| 条件 | 设置 | 回答的问题 |
|---|---|---|
| A 固定位 | 桌面标记位 ×10 | 重复性 / 可复现性 |
| B 偏移位 | 3 个区域（±5cm、±10cm）各 3–4 次，共 10 次 | 泛化 / 覆盖度 |

- 每配置 20 次（A10 + B10），4 个配置共 **80 次 ≈ 2h**；最终配置加测 10 次固定位（合计 30 次）。
- 次数理由：n=10 时 70% 的 95% CI 是 **[40%, 89%]**，无法分辨 20 个百分点的差异；n=20 仍宽，但足以发现 >30 个百分点的差距。**报告必须给 CI，不得只给百分比。**

### 5.3 顺序与漂移控制

- 配置间**交错**执行（固定序列 A B C D 循环），避免"后跑的配置赶上舵机热衰减"这类时间混杂；
- 会话末尾**重跑第一个配置 5 次**做重测；两次差异 >15 个百分点 → 当天成功率不可用于跨配置比较，需分两天复测。

### 5.4 图像置零消融（v1 缺，10 分钟）

最终配置在固定位跑 10 次，把两路图像输入置零（或替换为训练集均值）。成功率不降 → 策略没看图像，先查相机对位/分辨率，再谈模型与数据量。

### 5.5 记录格式

```
日期 | 配置 | 条件A/B | 试次 | 结果 | 失败码 | 用时 | 备注
```
失败码：`抓空 / 滑脱 / 撞物 / 超时 / 未对盒口 / 人为干预`。逐次记录，视频按试次命名，评估时不看 loss 与训练日志（盲测）。

## 8. 已知坑（本版新增/实测确认）

| # | 坑 | 处置 |
|---|---|---|
| 1 | `delta_timestamps` 单位是**秒**，传帧号会静默偏移 30 倍 | 已修 + 断言窗口索引 |
| 2 | `ACTPolicy.forward` 返回 `(loss, {"l1_loss","kld_loss"})`，**没有** `output["action"]` | 已修，改用 `loss_dict["l1_loss"]` |
| 3 | `--max_eval_samples>0` 取的是**前 N 帧**，不是均匀抽样 | 置 0，全量评估 |
| 4 | LeRobotDataset 默认解码全部视频；基线不用图像也必须显式移除特征 | 已修（0.236s → 0.004s/批） |
| 5 | `episodes` 列表顺序即语义，验证集必须放最后；`eval_split` 差 0.001 就切错且不报错 | 启动后 grep `Train/eval split` |
| 6 | 训练用原数据集的 51 条 stats 做归一化（含 val） | 披露；可选：为 s10/s25 生成独立切分 |
| 7 | `n_action_steps` 决定执行模式（100 = 开环 3.3s）；不同 run 必须一致 | 曲线阶段锁定 100；temporal ensemble 另做消融 |
| 8 | ep16-21 wrist_flex 活动量低（<5°） | 分层切分保证两侧都有，避免"验证集更简单" |
| 9 | 基线与 ACT 的 L1 单位不同（raw vs 归一化） | 分列，不直接比数字，比成功率 |
| 10 | 数据集无物体位姿元数据 | 下一批采集起记录区域标签（左/中/右 × 近/远） |

## 9. 预注册判定规则（先写死，防止事后解释）

| 观察 | 判定 | 动作 |
|---|---|---|
| `s41 − s25 < 10pp` 且 CI 重叠 | 41 条已达平台 | 停止扩采，转投**多样性**（位姿/物体/光照） |
| `s25 − s10 < 10pp` 且 CI 重叠 | 10 条即够本任务 | 数据量不是瓶颈，查模型与部署 |
| ACT 固定位 ≥90%，偏移位 <50% | 问题是覆盖，不是数据量 | 优先补位姿多样性，而非加条数 |
| 图像置零后成功率不降 | 策略未利用视觉 | 查相机对位/分辨率/归一化，再谈模型 |
| ACT − BC 基线 < 10pp 且 CI 重叠 | 视觉/架构收益不显著 | 回到数据质量与相机设置 |
