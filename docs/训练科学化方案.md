## 2. 训练命令模板（训练中自动报验证 loss）

**关键机制**（源码核实）：`lerobot-train` 原生支持 `--dataset.eval_split` 验证集，但默认
取"最后 N 条 episode"。`--dataset.episodes` 列表**保留给定顺序不排序**
（`lerobot_dataset.py:294`），因此**把 10 条验证集放在列表最后**，eval_split 取精确分数，
即可实现任意分层验证集，无需动数据集：

```bash
PYTHONPATH= nohup uv run --no-sync lerobot-train \
    --dataset.repo_id=zihao/so101_task1 \
    --dataset.root=/mnt/nvme_data/huggingface_cache/lerobot/zihao/so101_task1 \
    --dataset.episodes='[<训练集列表>, <验证集列表>]'   # ⚠️ 验证集 10 条必须在最后
    --dataset.eval_split=<见下表> \
    --policy.type=act --policy.push_to_hub=false \
    --output_dir=outputs/train/<run名> \
    --steps=50000 --batch_size=8 --save_freq=10000 --log_freq=200 \
    --eval_steps=2500 --max_eval_samples=2048 \
    --num_workers=4 --seed=1000 \
    > outputs/<run名>.log 2>&1 &
```

`eval_split` 取值表（`ceil(N×frac)=10` 的解，N=训练+验证总条数）：

| run | 训练条数 | N | eval_split | episodes 列表 |
|-----|---------|---|-----------|---------------|
| s10 | 10 | 20 | **0.500** | 训练 `[1,6,11,16,21,26,31,36,41,46]` + 验证 |
| s25 | 25 | 35 | **0.285** | s10 的 10 条 + `[2,3,7,8,12,13,17,18,22,23,27,28,32,33,37]` + 验证 |
| s41 | 41 | 51 | **0.196** | 全部 41 条训练集 + 验证 |

验证集列表（三个 run 固定不变，放最后）：
`[0,5,10,15,20,25,30,35,40,45]`

- 训练子集是**嵌套**的（s10 ⊂ s25 ⊂ s41），且全部避开 ≡0 (mod 5) 的验证条；
- 训练中每 2500 步在 2048 个验证样本上算 eval_loss（日志 `step N: eval_loss=…`），
  这是**同 run 内 checkpoint 选型**的第一信号；
- 50k 步 ≈ 4.2h/run（比 100k 减半：checkpoint 选型安全网下，先用 50k 拿全曲线，
  若 s41 的 val L1 在 50k 处仍在明显下降，再对最终配置加码）。

## 3. 基线：state-only BC（无图像 MLP）

**为什么**：没有基线的成功率没有意义。本基线回答"图像到底值多少"——若 ACT
不显著高于它，说明视觉未被利用或数据不足。

协议对齐：同样预测 100 步动作 chunk、同样 L1 损失、同样 MEAN_STD 归一化、
同样 41/10 切分。输入只有 6 维关节状态，无图像请求 → DataLoader 不解码视频，很快。

```bash
PYTHONPATH= nohup uv run --no-sync python myscript/train_bc_state.py \
    --steps 20000 --batch-size 256 --seed 1000 \
    --output-dir outputs/train/bc_state_task1 \
    > outputs/train_bc_state.log 2>&1 &
```

产物：`outputs/train/bc_state_task1/best.pt`（按 val L1 最优保存）+ `metrics.json`。
MLP（6→512→512→600，约 0.9M 参数）预期 20k 步 < 1h。

## 4. 离线验证评估（checkpoint 选型表）

`myscript/eval_val_l1.py`：对任意 ACT checkpoint 在 `_val` 上算 eval_loss 与
归一化 action L1：

```bash
PYTHONPATH= uv run --no-sync python myscript/eval_val_l1.py \
    --ckpt outputs/train/act_task1_s41_seed1000/checkpoints/<最优step>/pretrained_model
```

逐 ckpt 跑完填表（**选型按验证 L1，不按训练 loss**）：

| run | 最优 step | val action L1 | 真机成功率(10次) |
|-----|-----------|---------------|------------------|
| bc_state 基线 | — | （raw 单位，单列） | |
| s10 / s25 / s41 | | | |
| 51 条无切分（污染参考） | | ⚠️ 偏乐观 | |

> 跨 run 的归一化 L1 只做粗对比（不同子集的归一化统计略有差异）；
> 数据量结论以**真机成功率曲线**为准。

## 5. 真机 rollout 协议（每配置 10 次）

沿用 [`训练手册.md` §5](./训练手册.md) 的 rollout 命令（换 `--policy.path`）。
固定协议：同一积木初始位（桌面标记）× 10 次，记录：

```
日期 | run/ckpt | 次数 | 成功次数 | 失败模式（没抓到/对不准盒口/中途卡死/其他）
```

10 + 25 + 41 + 基线 ≈ 40 次 × ~1.5min（含复位）≈ 1.5h。成功率画成
**数据量–成功率曲线**（10/25/41 三点 + 基线水平线）——"51 条够不够"的唯一答案。

## 6. 最终配置 3 seed

按曲线选定配置（数据量、steps、是否 temporal ensemble）后：

```bash
# seed 1000 已有（该 run 即 seed1000），补 2000 / 3000：同命令改 --seed 与 output_dir
--seed=2000 --output_dir=outputs/train/act_task1_s41_seed2000

```

## 8. 已知坑（本方案新增）

- **episodes 列表顺序就是语义**：验证集必须在列表最后，乱序会让 eval_split 切到错误的条；
- `eval_split` 分数必须按上表精确取值，差一点 ceil 就会切出 9 或 11 条；
- 51 条无切分 run 的验证指标是污染的（验证 episode 在其训练数据里），只作参考行；
- ep16-21 wrist_flex 活动量低（<5°）：分层切分保证该段同时落在训练与验证，
  不会出现"验证集比训练集简单"的假象；
- 基线与 ACT 的 L1 单位不同（raw vs 归一化），表里分列，不直接比数字，比成功率。
