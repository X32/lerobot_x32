## 一、要采什么（每条 episode 自动记录的内容）

| 数据 | 来源 | 说明 |
|---|---|---|
| `observation.state` | 从臂 6 关节角度 | 自动记录（训练目标之一） |
| `action` | 主臂 6 关节角度 | 自动记录（训练输入→模仿对象） |
| `observation.images.front` | 相机 video0 | 主视角，**机位全程不许动** |
| `observation.images.third_person` | 相机 video2 | 第三视角，同上 |
| `task`（语言指令） | `--dataset.single_task` | 50 条必须**逐字一致** |
| timestamp / episode 索引 | 自动 | 30Hz，每条 ≤30s |

数据格式不用操心——record 命令把上面所有东西一次性写齐（parquet + 双 mp4）。

## 三、场景设计（ACT 泛化的关键）

**全程固定不变的：**
- 两个相机的位置和角度（挪一次 = 前后批次分布不一致，等于重录）
- 盒子的位置（固定在桌面上一个大致区域）
- 光照条件
- 抓取策略：**50 条用同一种手法**（同一侧接近、同样的抓取方式、相近的速度）。ACT 是模仿学习，策略太杂会出现"学成平均动作"

**每条之间轮换变化的：**
- 积木起始位置：在盒子前方划一片区域（如 5×2 网格），每条换一个格子，50 条正好轮完几轮
- 积木朝向可小幅随机
- 想练泛化就适度变，别让每条一模一样（否则学到的是"背下一条轨迹"）

**每条节奏**：10 秒复位时间（`reset_time_s=10`）内摆好积木 → 录制开始（有声音提示）→ 完整做一次「抓→移→放进盒子」→ **积木落盒立刻按 →** 进下一条（别拖尾）。

## 四、主命令（抄这条开录）

```bash
cd /mnt/nvme01/workplace/lerobot
uv run lerobot-record \
    --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=zihao_follower_arm \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30, fourcc: MJPG}, third_person: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
    --teleop.type=so101_leader --teleop.port=/dev/ttyACM1 --teleop.id=zihao_leader_arm \
    --dataset.no_stamp=true --dataset.repo_id=zihao/so101_task1 \
    --dataset.single_task="拿起桌上的积木放进盒子" \
    --dataset.num_episodes=50 --dataset.episode_time_s=30 --dataset.reset_time_s=10 \
    --dataset.push_to_hub=false
```

**录制中键盘**：`→` 完成即进下一条（别等满 30s）｜ `←` 这条砸了重录（计数不前进）｜ `Esc` 收工退出（已录的保留）。

**中断续录**（换批次/隔天继续）：命令完全相同 + 追加两个参数，并**改小 num_episodes**：

```bash
# 同一条命令末尾追加（例：已录 12 条，目标 50，本次再录 38）：
    --resume=true \
    --dataset.root=/mnt/nvme_data/huggingface_cache/lerobot/zihao/so101_task1 \
    --dataset.num_episodes=38
```

⚠️ 三个坑（2026-11-21 实测）：
1. resume 时 `--dataset.repo_id`、任务指令、相机配置必须和首次完全一致；
2. `--dataset.root` 必须写**数据集目录本身**（不是上级缓存目录）——缺了报 `ValueError: resume() requires an explicit 'root' directory`，只写上级目录会退回 Hub 下载 → 断网报 ConnectError；
3. **resume 模式下 num_episodes = 本次新录几条**（源码 `recorded_episodes` 从 0 计数），不是总条数——已录 12 条就填 38，录完正好 50。

嫌麻烦就直接用 `myscript/record_task1_resume.sh`（已配好全部参数，改批次只需改脚本里 num_episodes 一个数）。

**建议节奏**：5 批 × 10 条，批间 Esc 退出 → 做批次检查（见下）→ resume 续录。总时长约 1~1.5 小时（纯录制 ~35 分钟 + 复位和检查）。

## 七、常见情况处置速查

| 情况 | 处置 |
|---|---|
| 没抓住/放偏了 | 按 `←` 重录本条 |
| 动作做完还剩很多时间 | 按 `→` 直接进下一条 |
| **新一条刚开始就崩（ValueError: add_frame）** | `→` 在录制开始前被按了（0 帧空条，2026-11-21 实测）。本条没存上、已存的不受影响；看到 `Recording episode N` 后先做动作，1~2 秒内别按 `→`；跳复位只按一下 |
| 一条命令录几条？ | 连续录 `num_episodes` 条，自动循环"录→存→复位→下一条"，不用每条重跑命令；字母键 `n`/`r`/`q` 等价 →/←/Esc |
| 想休息/换批次 | `Esc` 退出，回来加**顶层参数** `--resume=true` + `--dataset.root=<数据集目录>`（注意不是 `--dataset.resume`；root 缺了报 ValueError，写错上级目录会撞 Hub 网络错误）。最稳：直接跑 `myscript/record_task1_resume.sh` |
| 中途碰了相机 | 尽量摆回原位（有胶印标记）；实在挪了就从头重录整个数据集 |
| 偶发 motor timeout | 重跑命令即可；反复超时查 3pin 线和 12V（手册 §5） |
| 续录报 `ImportError: 'deepdiff' is required` | 一次性补装：`uv sync --locked --extra deepdiff-dep`。只有 resume 触发兼容性检查才需要它，首次录制不装也能跑（2026-11-21 实测） |
| 磁盘 | 50 条 ≈ 1.5GB，无需担心 |
