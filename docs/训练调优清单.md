# 训练调优清单 — ACT × so101_task1 可调参数与优先级

> 2026-11-23 盘点。所有字段与默认值均在 `src/lerobot/policies/act/configuration_act.py`、
> `src/lerobot/transforms/transforms.py` 逐一核实（行号随代码版本，以 grep 为准）。
> 用途：rollout 基线出来后，按"观察到的失败模式 → 对应条目"选药，不做无假设扫参。
> 关联：[`训练手册.md`](./训练手册.md) §3 · [`训练科学化方案.md`](./训练科学化方案.md)

## 0. 前置结论：当前瓶颈不在超参

学习曲线（11-23，全量评估）已证：25→41 条 val L1 大跳 **−15%**，数据处于陡段。
超参调优的天花板约"+5%（同数据）"，补数据的预期是"+10% 以上"。所以顺序是
**先 rollout 定基线，再按失败模式对症选药**；每个改动 = 2.5h 训练 + 20min
全量评估，预算有限，只做有假设的实验。

## 1. 已完成/已排期的优化（本文不重复）

| 项 | 状态 |
|----|------|
| 训练步数 100k→20k~30k（s41 曲线证 20k 最优） | ✅ 11-23 |
| 学习曲线 + checkpoint 选型流程 | ✅ 11-23 |
| seed 2000/3000（测配方稳定性） | ⬜ 11-24 |
| temporal ensemble（推理期，`--policy.temporal_ensemble_coeff=1e-2 --policy.n_action_steps=1`） | ⬜ rollout 后 |
| 补录第二批数据（曲线背书，目标 70~80 条） | ⬜ 决策点 C |

## 2. 可调参数全清单（defaults 实测）

| 参数 | 当前值 | 作用 | 改动成本 |
|------|--------|------|---------|
| `optimizer_lr` | 1e-5 | 学习率（backbone 与头部同 lr） | 一次 2.5h 跑 |
| `optimizer_weight_decay` | 1e-4 | L2 正则 | 同上 |
| `dropout` | 0.1 | transformer 内 dropout | 同上 |
| `kl_weight` | 10.0 | VAE 正则强度（总损失 = L1 + kl×KL） | 同上 |
| `latent_dim` | 32 | VAE 隐变量维度 | 同上 |
| `chunk_size` / `n_action_steps` | 100 / 100 | 一次预测/执行步数（30Hz 下 3.3s） | 重训 + 部署联动 |
| `vision_backbone` | resnet18（IMAGENET1K_V1） | 视觉编码器 | 重训 + 显存↑ |
| `dim_model` / `dim_feedforward` / 层数 | 512 / 3200 / 4+1 | Transformer 容量 | 重训 + 过拟合风险↑ |
| `--dataset.image_transforms.enable` | **false** | 光度增强（brightness/contrast/saturation ±20%，默认配置齐） | **一个 flag，零代码** |
| `batch_size` | 8 | 批大小 | ⚠️ 显存硬约束（见 §5） |

## 3. 优先级

### 🥇 光度增强（单项最值得试）

```bash
--dataset.image_transforms.enable=true
```

- **为什么排第一**：采集与部署同房间同光照，但部署时光线必然波动（白天/夜晚/开灯）。
  训练没见过亮度变化，光线一变策略可能直接失灵；±20% 光度抖动是最便宜的"疫苗"。
- **用法**：作为独立变量单独测（不混进 seed 对照组）——先跑 seed 基线，再开增强跑一次，
  对比验证 L1 与 rollout 成功率。

### 🥈 微调项（各一次 2.5h 跑，按预期收益排）

1. **`optimizer_lr=2e-5`**：1e-5 偏保守，30k 恒定 lr 可能欠拟合；单旋钮，收益直接。
2. **`kl_weight` 5 或 20**：策略多模态性的旋钮。**对症药**——rollout 若见"动作在两个方案间
   摇摆"（如伸向中间）加大 kl；动作过于保守/呆滞则减小。等失败模式出来再动。
3. **`optimizer_weight_decay=3e-4`**：小数据正则，与 dropout 同族，边际收益一般。

### 🥉 结构性改动（41 条数据阶段不要碰）

- **`chunk_size` 100→60**：重规划更频繁、反应更快；等 rollout 出"任务后半段漂移"类失败再议。
- **`vision_backbone=resnet34` / `dim_model=768`**：容量↑。s10 已证明"容量相对数据过剩=背题
  加速"；数据到 70~80 条后再考虑。

## 4. 明确不能动 / 不建议动（已验证约束）

| 参数 | 原因 |
|------|------|
| `n_obs_steps` > 1 | ACT 源码硬约束（configuration_act.py post_init 直接报错） |
| crop_shape / resize | 本版 ACT processor 无此字段；且破坏"机位=输入分布"的采集一致性 |
| `batch_size` 16 | 8→5.5GB 线性外推 16≈11GB，**1080 Ti OOM 边缘**，不试 |
| lr scheduler | 本版 ACT 无现成调度器字段，恒定 lr 为现状；要加需改代码 |
| seed 调参 | seed 是抽样编号不是超参；为刷分挑 seed = 对考卷隐性过拟合 |

## 5. 决策树（rollout 之后怎么选）

```
明天 rollout 80 次 → 成功率基线（Wilson 95% CI）
 ├─ A. 成功率已可用 → seed 收尾 + 部署；超参一律不动
 ├─ B. 成功率低但失败模式清晰
 │     ├─ 光线敏感（换光照就崩）→ 光度增强 🥇
 │     ├─ 动作摇摆/犹豫       → kl_weight ↑
 │     ├─ 后半段漂移          → chunk_size 60 / temporal ensemble
 │     └─ 普适性地差          → 回决策 C
 └─ C. 各位置普适地差 → 补录第二批数据（曲线背书），超参靠后
```

预算纪律：**每个改动必须有假设**（"因为观察到 X，所以试 Y"）；
41 条数据撑不起网格搜索，只撑得起假设验证。
