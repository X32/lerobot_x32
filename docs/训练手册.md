### 1.2 参数逐项说明

| 参数 | 值 | 含义 / 为什么是这个值 |
|------|-----|----------------------|
| `--dataset.repo_id` | `zihao/so101_task1` | 数据集标识（本地数据，不推 Hub） |
| `--dataset.root` | `/mnt/nvme_data/huggingface_cache/lerobot/zihao/so101_task1` | **必须指向数据集目录本身**，不是缓存父目录；写错会触发 Hub 联网回退，离线时直接 ConnectError |

| `--output_dir` | `outputs/train/act_so101_task1` | checkpoint 与训练产物目录 |
| `--steps` | `100000` | 训练步数；51 条小数据集的常规起点（ACT 论文 5 万步级，保守取 10 万） |
| `--batch_size` | `8` | 1080 Ti 11GB 实测占 5.5GB 显存；OOM 时先降到 4 |
| `--save_freq` | `20000` | 每 2 万步存一个 checkpoint（共 5 个），训崩可回滚 |
| `--log_freq` | `200` | 每 200 步打一行训练指标 |
| `--num_workers` | `4` | DataLoader 进程数 |

outputs/train/act_so101_task1/
└── checkpoints/
    ├── 000001/          # 中途崩溃续训用的"最新"指针随保存滚动
    ├── 020000/
    │   └── pretrained_model/   # ← 部署时喂给 lerobot-rollout 的就是它
    ├── 040000/

### 1.4 监控

```bash
# 实时滚动看
tail -f outputs/train_act.log

# 提取干净的指标行（进度条 \r 会污染 grep，先 tr 再筛）
tr '\r' '\n' < outputs/train_act.log | grep "INFO" | grep "step:" | tail -3
```

指标行长这样（本机 13:28 实测）：

```
step:3K smpl:21K ep:44 epch:0.86 loss:1.056 grdn:44.739 lr:1.0e-05
      data_s:0.002 updt_s:0.299 step_s:0.301 smp/s:27 mem_gb:3.73
      l1_loss:0.347 kld_loss:0.071
```

| 字段 | 关注点 |
|------|--------|
| `loss` | 总损失 = L1 + 10×KL；健康曲线是前期快速下降后缓慢收敛 |
| `l1_loss` | 动作回归项，**最能反映策略质量**，应稳定下降 |
| `kld_loss` | VAE 正则项，先升后降是正常路径 |
| `grdn` | 梯度范数；持续爆大（>几千）说明 lr 过大或数据有脏帧 |
| `step_s` | 每步耗时；本机稳态 ~0.30s（3.3 step/s），明显变慢查是否被其他 GPU 进程抢占 |
| `mem_gb` | 显存占用；逼近 11GB 时当心 OOM |

GPU 状态另开终端：`watch -n 5 nvidia-smi`（期望：GPU 利用率 ~98%，显存 ~5.5GB）。

**速度基准**：100 000 步 ÷ 3.3 step/s ≈ **8.4 小时**。checkpoint 落盘时刻 ≈ 启动时间 + {1.7h, 3.4h, 5.0h, 6.7h, 8.4h}。

### 1.5 中断与续训

```bash
# 停止
pkill -f lerobot-train

# 续训：同一条命令加 --resume=true（或直接改 train_act_task1.sh 加上这个参数）
PYTHONPATH= uv run --no-sync lerobot-train \
    --dataset.repo_id=zihao/so101_task1 \
    --dataset.root=/mnt/nvme_data/huggingface_cache/lerobot/zihao/so101_task1 \
    --policy.type=act --policy.push_to_hub=false \
    --output_dir=outputs/train/act_so101_task1 \
    --steps=100000 --batch_size=8 --save_freq=20000 --log_freq=200 \
    --num_workers=4 --resume=true
```

续训机制（源码核实）：从 `output_dir/checkpoints/` 最后一个 checkpoint 恢复模型权重、优化器状态与**步数计数**；sampler 按 `step` 精确偏移，数据采样顺序与不间断训练逐样本一致。注意事项：

- `--steps` 等超参要与首次训练一致（step 计数是绝对的，改成不同值会提前停或不停）；
- 恢复点只在 checkpoint 粒度（2 万步），上次保存之后的进度会重训；
- 若 checkpoint 全没来得及存就崩了（前 1.7 小时），只能从头跑。

## 2. 原理

### 2.1 ACT 是什么

ACT（Action Chunking with Transformers，ALOHA 团队 2023）= **CVAE + Transformer 的模仿学习策略**。它不是逐步预测下一个动作，而是一次预测**一整段未来动作序列**（chunk），执行时按序回放，天然平滑、抗抖动。

```
            观测 (2×480×640 图像 + 6 关节位置 + 6 关节速度)
             │                          │
    ┌────────▼────────┐        ┌────────▼────────┐
    │ CVAE 编码器(仅训练) │        │  视觉编码器 ×2   │
    │ 真实未来动作+观测   │        │ resnet18+       │
    │ → 均值方差 → z     │        │ spatial softmax │
    └────────┬────────┘        │ (每图 → 512维)   │
             │    z(32维)      └────────┬────────┘
             └──────────┬───────────────┘
                 ┌──────▼──────┐
                 │  Transformer │  encoder 4 层 / decoder 1 层
                 │  解码器      │  dim 512 / ffn 3200
                 └──────┬──────┘
                 ┌──────▼──────┐
                 │ 动作序列头    │ → 100 步 × 12 维动作
                 └─────────────┘
```

**推理时**没有真实未来动作，编码器整路不参与，z 取零向量（先验），纯解码器前向。

### 2.2 关键超参（configuration_act.py 默认值，本仓库实测核对）

| 超参 | 值 | 含义 |
|------|-----|------|
| `chunk_size` | 100 | 一次预测 100 步动作；30Hz 下 = 3.3 秒 |
| `n_action_steps` | 100 | 每次推理实际执行 100 步（=chunk 全长），然后重新观测再推理 |
| `n_obs_steps` | 1 | 只用当前帧观测（ACT 固定，>1 会报错） |
| `vision_backbone` | resnet18 | ImageNet 预训练（IMAGENET1K_V1），每个相机一份 |
| `dim_model` / `dim_feedforward` | 512 / 3200 | Transformer 宽度 |
| `n_encoder_layers` / `n_decoder_layers` | 4 / 1 | 非对称结构（官方配方） |
| `use_vae` / `latent_dim` / `kl_weight` | true / 32 / 10 | CVAE 部件；总损失 = L1 + 10×KL |
| `optimizer_lr` | 1e-5 | backbone 与头部同 lr |
| 参数量 | 52M（51,597,190 实测） | 1080 Ti 无压力 |

两点对理解训练行为很重要：

- **图像不裁剪不缩放**：本仓库版本的 ACT processor 没有 crop/resize 字段，两路 480×640 原图直接进 resnet18。所以采集时**机位就是模型的输入分布**——部署时必须把相机摆回采集时的位置（脚架上有胶带标记）。
- **归一化用全数据集统计**（MEAN_STD）：输入图像/关节、输出动作都按 51 条数据算出的均值方差归一。换数据集重训时统计会重算，无需手工干预。

### 2.3 数据契约

| 项 | 值 |
|-----|-----|
| 数据集 | `zihao/so101_task1`，51 条（删 1 条静止废条后），24 150 帧 |
| 采集 fps | 30（训练时按数据集元信息自动对齐） |
| 观测 | `observation.images.front`（全景，video0）+ `observation.images.third_person`（近景特写，video2）+ 6 关节 pos/vel |
| 动作 | 6 关节目标位置（单臂 SO-101） |
| 任务语句 | `拿起桌上的积木放进盒子`（single_task，全数据集一致） |
| 有效时长 | 51 × ~13s ≈ 11 分钟演示数据 |

51 条对 ACT 是"够起步、不富余"的量：同场景同机位同任务，ACT 通常 50 条上下可出可用策略；但泛化到新积木位置的能力弱，改进路线见 §3。

## 3. 改进方案（按优先级排）

### 3.1 第零步永远是：先 rollout 拿到真实成功率

训练 loss 降不降得好**不等于**真机能完成任务。训完先跑 10 次真机 rollout 记成功率（§5），后续一切改进以这个数字为基线，避免盲目调参。

> 本节的改进是"调参级"。验证集切分、基线对照、数据量学习曲线、seed 统计等**实验科学化**改进见 [`训练科学化方案.md`](./训练科学化方案.md)（41/10 分层切分已完成）。

### 3.2 零成本改进（只改推理配置，不重训）

**时间集成（temporal ensemble）**：ACT 每个 chunk 执行中其实可以每步都重新推理，把新旧 chunk 在重叠区按指数权重混合，动作更平滑，成功率常有可观提升。代价是推理频率从每 3.3s 一次变为每步一次（本机 1080 Ti 推单帧 ACT 约 30-50ms，30Hz 控制内可承受）。

```bash
# 在 §1.2 完整命令基础上追加（policy 级参数）
--policy.temporal_ensemble_coeff=1e-2
```

⚠️ 仓库 constraint：`temporal_ensemble` 生效时要求 `n_action_steps=1`，即：

```bash
--policy.temporal_ensemble_coeff=1e-2 --policy.n_action_steps=1
```

（不改训练，checkpoint 直接兼容——这两个都是推理期行为。）

### 3.3 重训类改进（按性价比排序）

| 优先级 | 改什么 | 命令差异 | 预期 | 成本 |
|--------|--------|----------|------|------|
| 1 | **补数据**：针对 rollout 失败的场景补录 20-50 条（如积木在最左/最右时失败，就专录那两个区域） | 数据集沿用 `zihao/so101_task1`，`lerobot-record --resume=true`（坑见采集手册 §3.3） | 最直接解决"特定工况失败"，模仿学习第一条铁律：缺什么录什么 | 每条 ~40s |
| 2 | **训练步数**：loss 还在明显下降就说明 100k 不够 | `--steps=200000`（配合 `--resume=true` 从 100k 续） | 小数据集后期收益递减，先看曲线再决定 | +8.4h |
| 3 | **learning rate**：loss 震荡不降时降 lr | `--policy.optimizer_lr=5e-6` | 1e-5 对小数据可能偏大 | 同一次重训 |
| 4 | **batch size**：显存富余且 loss 噪声大时升 | `--batch_size=16`（先确认显存 ~11GB 内不 OOM） | 梯度更稳，1080 Ti 上 16 大概率撑得住（8 占 5.5GB） | 同一次重训 |
| 5 | **chunk_size**：任务周期 ~13s，chunk 3.3s 偏短 | `--policy.chunk_size=60`（2s）改短试响应，或保持 100 | 改 chunk 必须重训，别对 51 条数据动它，优先级压后 | +8.4h |
| 6 | **换策略**：见 [`模型选型指南.md`](./模型选型指南.md)（SmolVLA 等） | `--policy.type=...` | 51 条小数据上 ACT 仍是性价比之王，除非有语言指令泛化需求 | 重新摸索 |

### 3.4 明确不建议

- **一上来就换大模型/大 backbone**（resnet50、VLA）：51 条小数据会先过拟合，收益为负。
- **改图像预处理**（crop/resize）：本版本 ACT 没有这些字段，没有现成开关，改动涉及 processor 源码且破坏与采集分布的一致性。
- **混合新旧场景数据**：机位/光照大改后的数据混进旧数据集会互相拉扯；新场景建议另立 repo_id 重训，别 resume。

## 4. 错误处理速查表

按"报什么错 → 什么原因 → 怎么修"组织，全部来自本机实测踩坑。

### 4.1 训练启动阶段

| 症状 | 原因 | 修复 |
|------|------|------|
| `CUDA initialization: The NVIDIA driver on my system is too old (found version 12080)` | torch 被 lockfile 同步回 cu132，1080 Ti 驱动 570 不认 | 重装 cu126 轮子：`uv pip install --no-sync /mnt/nvme01/torch_wheels/torch-2.8.0+cu126-*.whl /mnt/nvme01/torch_wheels/torchvision-0.23.0+cu126-*.whl`；事后自查为什么 `--no-sync` 没带 |
| `import torch` 能过但 `torch.cuda.is_available()=False` | 同上（cu132 残留）或 GPU 被独占 | 跑 §0 的 10 秒体检；`nvidia-smi` 看占用进程 |
| `ImportError: 'accelerate' is required but not installed` | 精简环境缺包 | `uv pip install --no-sync accelerate --index-url https://mirrors.aliyun.com/pypi/simple/`（**别用 uv sync 补**，会连 torch 一起动） |
| `ValueError: 'repo_id' argument missing` | `--policy.push_to_hub=true`（或缺省走 Hub）但没给 `--policy.repo_id` | 加 `--policy.push_to_hub=false`（注意是 policy 级参数，顶层 `--push_to_hub` 不存在） |
| `ConnectionError ... huggingface.co`（下载数据集/模型） | `--dataset.root` 写成了缓存**父目录**而不是数据集目录本身，元数据找不到 → 触发 Hub 回退，离线即炸 | root 指到 `.../lerobot/zihao/so101_task1` 这一级 |
| `outputs/train_act.log: No such file or directory` | 仓库根没有 `outputs/` 目录 | `mkdir -p outputs` 后重跑 |
| 裸 `uv run` 卡在 Installing/Resolving | lockfile 重装依赖（含换掉 torch） | Ctrl+C，改用 `uv run --no-sync`；若已被换，按本表第一行重装 cu126 |
| `Unexpected optimization option test_configs.force_filter_reduction_configs`（inductor 报错） | 有人装了 torchcodec，或 praxis 补丁被回退 | `uv pip uninstall --no-sync torchcodec`；`git diff src/lerobot/policies/praxis/` 确认 3 处补丁还在 |

### 4.2 训练运行阶段

| 症状 | 原因 | 修复 |
|------|------|------|
| `CUDA out of memory` | batch 过大 / 显存被其他进程挤占 | `--batch_size=4` 重跑（加 `--resume=true` 从上个 checkpoint 续）；`nvidia-smi` 查谁在占卡 |
| loss 长期不降（<1k 步就 >10 平坦） | 数据损坏（视频解码全黑/空帧） | `uv run --no-sync python myscript/check_dataset.py` 全量质检 |
| `step_s` 从 0.3 涨到 >1 | DataLoader 慢（视频解码瓶颈）或被抢 CPU | 确认没人跑大任务；可试 `--num_workers=8` |
| 进程消失但无 OOM 日志 | 被系统 OOM-killer 杀（内存不足，num_workers 开太多） | `dmesg \| tail` 确认；降 `--num_workers=2` 续训 |
| 训练好好的突然 ` ConnectionResetError`/hub 报错 | 中途触发联网（wandb/upload 等） | 训练本体纯离线，若加了上报参数去掉它；数据加载已本地化不受影响 |

### 4.3 策略加载 / praxis 相关

| 症状 | 原因 | 修复 |
|------|------|------|
| `ImportError: cannot import name 'FlexKernelOptions'`（加载任意策略时） | `policies/__init__.py` 或 `praxis/__init__.py` 的容错补丁被回退，praxis 在 torch 2.8 上硬导入 | 恢复补丁（`git log --oneline -3 src/lerobot/policies/` 对照；3 个文件见下） |
| `Unexpected optimization option test_configs...`（同 4.1 末行） | `praxis_core/layers.py` 补丁被回退 | 同上 |

补丁清单（勿回退，勿"顺手修复"）：

1. `src/lerobot/policies/__init__.py` — 对 praxis 的导入容错
2. `src/lerobot/policies/praxis/__init__.py` — 包级 try/except，旧 torch 上 `__all__=[]`
3. `src/lerobot/policies/praxis/praxis_core/layers.py` — `_compile_or_eager` 包住 `torch.compile`（含 2.15-only 的 compile option）

### 4.4 视频解码（训练时读数据集）

| 症状 | 原因 | 修复 |
|------|------|------|
| 日志出现 `Falling back to 'pyav'` | 正常现象 | 不用管。torchcodec 已卸载（无 ABI 匹配轮子），torchvision 自动走 pyav 后备，解码正确性已验证 |
| AV1 解码报错 / 花屏 | 老版本 pyav 缺 AV1 支持 | `uv pip install --no-sync -U av --index-url https://mirrors.aliyun.com/pypi/simple/` |

## 5. 训完部署（真机 rollout）

> 部署入口是 **`lerobot-rollout`**（源码确认：lerobot-record 已拒绝策略部署，`policy.path` 由 rollout 接管）。
> 本节命令按源码 RolloutConfig 编写；**首次真机执行前先空跑验证**（手放急停位，见采集手册安全节）。

### 5.1 部署前检查

1. 场景复位：积木初始位置、盒子位置、双相机机位对准脚架胶带标记（§2.2 说过：机位=输入分布）；
2. 从臂上电解锁：`uv run --no-sync lerobot-setup-motors`（或直接跑 rollout，它会自检 torque）；
3. 挑 checkpoint：默认用最后的 `checkpoints/100000/pretrained_model`；对比用中间 ckpt 把路径换掉即可。

### 5.2 基础部署命令（base 模式：自主执行、不录数据）

```bash
cd /mnt/nvme01/workplace/lerobot
PYTHONPATH= uv run --no-sync lerobot-rollout \
    --strategy.type=base \
    --policy.path=outputs/train/act_so101_task1/checkpoints/100000/pretrained_model \
    --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=zihao_follower_arm \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, third_person: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30}}" \
    --task="拿起桌上的积木放进盒子" \
    --duration=30
```

要点：

- `--robot.*` 与 `--robot.cameras` 参数**照抄采集脚本** `myscript/record_task1_resume.sh`（同机位同分辨率），只有相机 fourcc 略去（rollout 只读不写，用默认即可）；
- `--policy.path` 填本地目录（指向 `pretrained_model`，里面要有 config.json + 权重）或 Hub repo id；
- `--duration=30`：单次 rollout 秒数；不加则无限跑，Ctrl+C 停；
- 想顺手录下来（存成数据集，可回放/可分析）：`--strategy.type=episodic --dataset.repo_id=zihao/so101_task1_rollout --dataset.push_to_hub=false`；
- 可视化叠加窗口：`--display_data=true`。

### 5.3 成功率评估流程（改进的起点）

1. 固定积木初始位（标记在桌面），跑 10 次 `--duration=30`，记录成功次数与失败模式（没抓到？抓到了没对准盒口？中途卡死抖动？）；
2. 若启用 §3.2 时间集成再跑 10 次对比；
3. 失败模式定向补数据（§3.3 优先级 1），补完 resume 续训，回到第 1 步——这就是模仿学习的迭代循环。
