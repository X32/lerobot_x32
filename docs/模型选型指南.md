# 模型选型指南（SmolVLA / ACT / π0 / LingBot-VLA）

> 本文整理自 v0.7.1 仓库调研（2026-11），是 [`ARCHITECTURE.md`](../ARCHITECTURE.md) 中"训练/部署"环节的展开。
> 部署硬件细节（Jetson / 香橙派算力分析）见文末"边缘硬件选型"一节。

## 四个模型的定位差异

| | **ACT** | **SmolVLA** | **π0** | **LingBot-VLA 2.0** | **LingBot-VA 1.0** |
|---|---|---|---|---|---|
| 类别 | BC·单任务 | BC·通用 VLA | BC·通用 VLA | BC·通用 VLA | **世界模型**（视频+动作自回归） |
| 参数量 | ~几 M | 450M | 3.3B | 4B + MoE 专家 | 10B+（5B DiT + 冻结编码器） |
| 动作生成 | CVAE 直接出动作块 | flow matching（小专家） | flow matching | flow matching，**55 维跨本体统一空间** | 双流去噪（视频流 20 步 + 动作流 50 步） |
| 语言指令 | ❌ 无 | ✅ 有 | ✅ 有 | ✅ 有 | ✅ 有 |
| 演示数据需求（微调） | 每任务 ~50 条 | 数十~数百条 | 更多、要求更高 | 中等，需映射本体到 canonical slots | 重资源，学术向 |
| 训练硬件 | 单卡甚至 CPU | 消费级 8GB GPU | 桌面 GPU/A100 级 | 16GB+ GPU | 数据中心（A100/4090 级） |
| 部署硬件 | 树莓派/香橙派 CPU 都行 | Jetson 流畅 / 香橙派 CPU 勉强 | 8GB+ GPU 或远程 | 同 π0 且更重 | 服务器/集群 |
| 泛化能力 | 无（换任务=重录重训） | 中（新指令/新场景 few-shot 适配） | 强（预训练数据万小时级） | 强 + **跨机器人形态迁移** | 强（能"想象"物理后果） |
| 落地速度 | **最快**（一晚训完） | 天级 | 周级 | 周级 | 实验阶段 |

仓库内对应目录：`src/lerobot/policies/{act, smolvla, pi0, lingbot_vla_v2, lingbot_va}`。

**本质差异一句话**：ACT 是"背下这一件事"；SmolVLA/π0/LingBot-VLA 是"预训练了大量机器人的通用底座，微调适配你的任务"，差别只在底座大小和迁移能力；LingBot-VA 1.0 是另一个物种——它会先在"脑内"生成未来视频预演再出动作。

## 选型决策树

```
你的任务能用固定动作序列解决吗？
├─ 能（固定工位、单一抓放/插件/分拣）
│   → ACT：50 条演示 + 一晚训练 + 最便宜的硬件 ✅ 起点永远从这开始
│
└─ 不能（指令多变/场景变化/多任务切换）
    → 需要语言理解和泛化 → VLA 路线，再按预算分：
        ├─ 硬件受限（边缘端部署/预算紧）
        │   → SmolVLA（450M，消费级硬件设计目标就是它）
        ├─ 任务复杂灵巧/长程/高成功率要求 + 有 GPU 预算
        │   → π0（生态最成熟、社区实践最多）
        └─ 多种机器人形态要共用一个策略（跨本体）
            → LingBot-VLA 2.0（55 维统一动作空间是它的独门卖点）
                ※ 世界模型/需要"预判后果"的研究场景 → LingBot-VA 1.0（数据中心预算）
```

## 项目选型的四个评估维度

按顺序问自己：

1. **数据现状**——手里有多少演示？
   `<100 条 → ACT/SmolVLA 微调`；`数据丰富且多任务 → VLA 微调`；`几乎没有 → 先录，别想跳过采集`
2. **任务不确定性**——指令和场景会变吗？
   固定 → ACT；会变 → VLA；变到不可枚举 → 越大的底座越稳
3. **硬件两本账**——训练侧 + 部署侧分开算：
   边缘部署选 ACT/SmolVLA，π0/LingBot 必配服务器 + policy-server 架构
4. **迭代成本**——上线后任务改了怎么办？
   ACT：重录重训（几小时）；VLA：增量微调（几天）——VLA 换来的是"改任务不用推倒重来"

## 边缘硬件选型（部署侧速查）

| 模型 | Jetson Orin Nano 8G | 香橙派 5 系（RK3588，纯 CPU） | 服务器 GPU（8GB+） |
|---|---|---|---|
| ACT | ✅ 极快 | ✅ 无压力 | ✅ |
| SmolVLA | ✅ 流畅（每 chunk 亚秒级，异步推理） | ⚠️ 能跑但贴线（每 chunk 估 0.5-2s，预算 1.67s） | ✅ |
| π0 | ❌ 本地（内存/算力都不够） | ❌ | ✅ 原生 bf16 |
| LingBot-VLA 2.0 | ❌（bf16 权重 ~8-10GB 超内存，无量化移植） | ❌ | ✅ |
| LingBot-VA 1.0 | ❌（20GB+ 内存门槛 + 算力爆炸） | ❌ | 需 A100/4090 级 |

跨硬件架构：**边缘端当"手脚"（电机+相机+执行）+ 服务器跑 `lerobot-policy-server` 当"大脑"**，对应模块 `remote_inference/` + `transport/`。断网自主任务才需要本地跑得动模型。

Jetson 部署注意：LeRobot 要 Python ≥3.12（JetPack 自带 3.10，用 uv 装独立 CPython）；PyTorch 要 NVIDIA aarch64 CUDA 轮子；headless + `jetson_clocks` 锁频。香橙派注意：RKNN NPU 不支持 PyTorch Transformer，SmolVLA 只能纯 CPU，异步推理必开。

## 落地路线（SO-101 项目）

LeRobot 的架构红利：**所有模型共用同一条流水线**（采集格式、训练入口、评估方式全一样），换模型只改一个参数：

```bash
--policy.type=act → smolvla → pi0
```

阶梯式路线：

```
① ACT    先跑通：遥操→录50条→训一晚→真机验证  （一周内见效，验证整条链路+数据质量）
② SmolVLA 数据够了升级：加语言指令，消费级GPU微调   （任务开始多变时）
③ π0/LingBot-VLA  有真GPU预算 + 任务确实超出SmolVLA能力才上（大概率用不到）
```

**反面提醒**：不要项目第一天就上 π0——花最贵的算力解决 ACT 就能解决的问题，且数据质量没被 ACT 验证过，微调 VLA 等于把垃圾数据喂给大模型。先小后大，模型升级永远可以后置。
